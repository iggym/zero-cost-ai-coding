1. mkdir -p .github/workflows

4. Check the Actions tab in your GitHub repo

How to use

  1. Pick your project type — Node.js, Python, Go, or Rust.
  2. Check the steps you need — lint, test, build, deploy. The workflow regenerates live as you change options.
  3. Set your version and package manager (Node.js only for pkg manager).
  4. Copy the YAML into .github/workflows/ci.yml in your repo.
  5. Commit and push — GitHub Actions picks it up automatically.

What you get that starters don't give you

  • Dependency caching — keyed to your lockfile, so CI runs are fast after the first one.
  • Current action versions — v4 checkout, v4 setup-node, v5 setup-python, v5 setup-go. No deprecated warnings.
  • Job ordering — build waits for lint+test, deploy waits for build. No wasted minutes on broken code.
  • Manual trigger — workflow_dispatch is included so you can re-run from the Actions tab.
  • Deploy guard — deploy only runs on main, not on PRs.

What breaks

  • Private repos: GitHub Actions free tier is 2,000 minutes/month. A typical lint+test run is 2-5 minutes — you'd need 400+ runs/month to hit it.
  • Custom commands: The workflow assumes standard commands (npm test, npm run lint, npm run build). If your project uses different commands, edit the YAML after copying.
  • Monorepos: This generates a single-project workflow. Monorepo setups need path filters and separate jobs — edit accordingly.
  • Action versions change: The generated YAML pins to current major versions (v4, v5). If GitHub releases v5 for checkout, update the action ref.
GitHub Actions free tier: unlimited for public repos, 2,000 min/month for private — docs.github.gov. Generated workflows use actions from github.com/actions.
