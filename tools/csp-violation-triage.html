CSP Violation Triage

Paste a pile of raw CSP violation reports — the legacy {"csp-report":{…}} POST body, the Reporting API {"type":"csp-violation","body":{…}} shape, or both mixed — and get them deduplicated into groups, browser-extension noise pulled out separately, and a corrected Content-Security-Policy header built from the original-policy in the reports themselves. Runs entirely in the tab: no upload, no account, no report cap.

Free-tier limit: none. Parsing and policy generation are plain JavaScript in your browser tab — no API call, no key, no per-report quota. The only ceiling is your device's memory.

What it replaces

Hosted CSP report collectors charge by report volume: Csper Basic is $50/month for 3 sites and 100,000 reports/month (14-day trial, then billed); Report URI Starter is $54.99/month ($659.88/yr) for 1 domain and 100K monthly events. Both prices read off their own pricing pages on 2026-08-15. Those products do things this page does not — a live collection endpoint, retention, alerting. This page only does the part you do at 2am with a JSON blob in your clipboard: group it, throw out the extension noise, and tell you what the policy should say.

How to use it

  
    
    
  1. Deploy Content-Security-Policy-Report-Only with a reporting destination so nothing on your site actually breaks while you collect. Reports arrive as JSON POST bodies.
    2. 
    
  2. Dump the collected bodies into the box above — array, NDJSON, or a single one. Hit Triage reports.
    3. 
    
  3. Read the groups. ignore rows are browser-extension traffic and shouldn't be added to your policy. fix rows are things allowlisting won't solve (mixed content). allow rows become source tokens in the generated header.
    4. 
    
  4. Copy the proposed header, ship it as report-only first, and re-triage the next batch before switching to enforcing.
    5. 
  


  
What breaks

  
    
    
  • Inline script/style violations can't be auto-fixed here. script-sample is truncated to the first 40 characters by design (per MDN's report-uri docs), so a correct 'sha256-…' hash cannot be computed from a report. Those groups are marked review and suggest a nonce, not a blind 'unsafe-inline'.
    • 
    
  • Cross-origin blocked-uri values are already truncated by the browser to scheme/host/port when they differ from the document origin, so the generated allowlist is origin-level. If you want path-level sources you have to narrow them by hand.
    • 
    
  • If no report carries an original-policy, there's nothing to merge into, so the generator starts from default-src 'self' and says so above the output.
    • 
    
  • Chrome reports script-src-elem/style-src-elem even when you wrote script-src. The generator adds sources to whichever directive your original policy actually declares, falling back to the base directive.
    • 
    
  • Everything is in-memory. Reloading the tab loses the input — export the JSON if you want it back.
    •
