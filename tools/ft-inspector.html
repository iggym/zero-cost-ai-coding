01 · Why this exists

Dataset prep is where fine-tuning quietly fails.

OpenAI accepts a JSONL file where each line is a conversation in Chat Completions shape — but a single malformed line, an empty content field, or a stray trailing comma rejects the whole upload. The OpenAI community forum is full of "invalid training file" and "does not appear to be valid JSON format" threads ([example](https://community.openai.com/t/fine-tuning-error-the-job-failed-due-to-an-invalid-training-file-unexpected-file-format-expected-either-prompt-completion-pairs-or-chat-messages/726568)). Inspecting the file locally before upload is a $0, in-browser job — no need for a paid LLM-dev platform just to validate rows.

What breaks / honest limits

Token counts are a rough estimate using OpenAI’s “≈4 characters per token” rule of thumb for English — real tokenizers differ, especially for code, JSON, and non-English text, so treat numbers as a budget proxy, not an exact count. Dedupe is a normalized exact match (roles + content), not semantic similarity — reworded but equivalent examples will NOT merge. Validation covers the chat messages shape (role + content, at least one message); it does not enforce OpenAI’s full content-policy or per-model rules. Very large files (100k+ lines) will slow the single-threaded parser. Exported cleaned JSONL drops malformed rows and keeps one copy of each duplicate.

05 · Build this yourself

Parameterized prompt pack

This teaches the pattern — not just this tool. Pick your model tab, copy, replace the variables, and run. Every schema below is the provider’s current real format, verified 2026-08-16.

How to use this pack

1. In a chatbot: Pick your model tab (e.g. Anthropic), click Copy on the system block and the user block, paste into claude.ai / chat.openai.com / aistudio.google.com, replace every {{variable}} with your problem, send.

2. In code: Use the model’s tool/function block — it is a ready tools payload for the OpenAI / Anthropic / Google API. Replace {{variables}} programmatically.

3. All prompts are parameterized with {{double-curly}} variables you must fill. Never hardcode the example problem.

4. Open-weight (local / vLLM / Ollama with Llama 3.1, Mistral, Qwen2): use the plain system/user template with strict JSON output — no tool wrappers needed.
