What Breaks

  • Browser RAM: In-browser WASM models require ~500MB of RAM. If your tab crashes, close other tabs.
  • The real limiting resource is GitHub Pages, not OSV: OSV.dev currently publishes no rate limit, but that's a courtesy, not a guarantee — batch requests via querybatch rather than hammering it. The bandwidth cap that will actually bind first, on a popular page, is GitHub Pages' soft 100GB/month limit.
  • Hallucinated Context: The AI generates the summary, which may hallucinate. The fix command is extracted strictly from OSV JSON, ensuring your patch is deterministic.
  • Missing Fixes: Some CVEs have no published fix version yet. The tool will output "No fix available."

Three Things This Teaches

1. OSV.dev needs no key at all — NVD's is only optional
NVD's API 2.0 doesn't strictly require a key either, but unauthenticated requests are held to 5 requests per rolling 30-second window versus 50 with a free key — in practice that pushes most tooling toward requesting one. OSV.dev skips that step entirely: no key, and its own docs currently state no rate limit at all, which is what makes a genuinely zero-setup, browser-native security tool possible.
2. Transformers.js enables private security scans
By running DistilBART via WASM, confidential dependency topologies never egress to a third-party AI provider, sidestepping corporate firewall restrictions and privacy concerns.
3. Stack ordering is forced by context limits
OSV fetch MUST precede AI summarization because raw OSV JSON dumps exceed the context window of small local models. We extract the minimal text first, then summarize.
