Source Map Remapper

Source Map Stack Remapper

Paste a minified stack trace and a .map file, get original file:line:column plus a snippet from sourcesContent. VLQ decode runs in this tab. ∞ runs — no API, no key, no quota

What it replaces: the source-map unminification step people buy Sentry Team for ($26/mo billed annually, 50k errors included). This does only that lookup. Sentry is a full error tracker; this is not.

How to use

  1. Drop or paste a v3 source map (the JSON .map from your build). Nothing is uploaded.
  2. Paste the production stack (V8/Node at … or Firefox fn@file:line:col).
  3. Hit Remap. Copy the rewritten stack or the JSON.

or drop a file here · also accepts a JS file with a sourceMappingURL=data:…base64 comment

Map stays in this tab. If it contains sourcesContent, that is your original source — treat it like source code, not a secret-free artifact.

0s saved on this remap assumption: est. 45s per remapped frame to match a generated line:col against a raw mappings string by hand — not a published study

What breaks

  
    
    
  • Index maps whose sections only have a url (not an inline map) — this page does not fetch.
    • 
    
  • Very large maps (tens of MB) can stall the tab while VLQ-decoding mappings.
    • 
    
  • Frames without a column (at foo (file.js:12)) are not parsed — V8/Firefox stacks almost always include one.
    • 
    
  • One-field mapping segments are unmapped generated code; they stay as-is.
    • 
    
  • No sourcesContent means you get a path but no snippet.
